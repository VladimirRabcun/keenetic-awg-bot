# Telegram-бот и Mini App для AWG Manager / Keenetic

Telegram-бот и web-панель по архитектурному образцу [pumbaX/awg-multi-script](https://github.com/pumbaX/awg-multi-script/tree/main/awg_bot). Mini App использует исходные стили, SVG-иконки и адаптированные элементы интерфейса AWG Toolza: меню в шапке, настройки вида, солнце/луна, сводка и три раскладки главной. Логотип взят из AWG Manager. Лицензии и источники сохранены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Вместо `awg2` используется HTTP API AWG Manager. Python 3.9+ с SSL, без pip и бинарных расширений: подходит для Entware ARM/MIPS при наличии пакета Python соответствующей архитектуры.

## Возможности

- Приватный Telegram-чат: whitelist ID, список управляемых туннелей, карточки, start/stop/restart, connectivity, WAN, система, ping-check, логи и диагностика.
- Mini App: адаптивные карточки, тема Telegram, подтверждение stop/restart, обновление каждые 15 секунд, те же действия через подписанный initData.
- Мониторинг: изменение статуса туннеля, результатов штатного ping-check, WAN; недоступность AWGM после трёх проверок и восстановление. Уведомления получает ADMIN_ID. Все ALLOWED_IDS имеют одинаковые права управления.
- Настройка уведомлений сохраняется атомарно в STATE_DIR. При перезапуске первая выборка — базовая, без массовых уведомлений. Очередь до 100 сообщений находится в памяти; при отсутствии Интернета доставка повторяется, после перезапуска очередь теряется.
- Статус running не означает наличие Интернета. Связность проверяется явно; latency показывается в результате connectivity. Штатный ping-check настраивается в AWGM, бот умеет показывать статус и запускать общую проверку.

Внешние/нативные и sing-box туннели не управляются этой версией: их модели и операции отличаются от `/control/*`. Создание, удаление, импорт конфигов, маршрутизация и управление роутером не входят в проект.

## Установка на Keenetic

### Быстрая установка из GitHub

После установки Entware выполните в SSH-консоли роутера:

```sh
opkg update && opkg install python3 ca-bundle curl && mkdir -p /opt/tmp && curl -fsSL https://raw.githubusercontent.com/VladimirRabcun/keenetic-awg-bot/main/bootstrap.py -o /opt/tmp/awg-bot-bootstrap.py && /opt/bin/python3 /opt/tmp/awg-bot-bootstrap.py
```

Установщик скачает проверенный commit, закреплённый в INSTALL_COMMIT, проверит пути архива, установит файлы и запросит BOT_TOKEN, ADMIN_ID, адрес AWGM и API-ключ. Токен и ключ вводятся без отображения. WEBAPP_URL можно оставить пустым и настроить HTTPS позже. Конфиг сохраняется с правами 600, затем выполняется проверка API и предлагается запуск. При существующей установке bootstrap останавливается; обновление описано ниже. Анонимный GitHub API не используется, поэтому его лимит запросов не мешает установке.

Повторная настройка: `/opt/bin/python3 /opt/awg-bot/configure.py` (сначала остановите сервис; затем запустите). Предыдущий конфиг сохраняется в `/opt/etc/awg-bot.conf.bak` с правами 600. Он также содержит секреты. Проверка загрузки использует HTTPS с системным CA; источник установки — указанный GitHub-репозиторий.

### Установка из архива

1. Установите Entware и AWG Manager, убедитесь, что его web-панель работает. В AWGM → Настройки → Расширенные сгенерируйте API-ключ. Узнайте фактический порт (документированный default — 2222, но он может измениться).
2. Создайте бота через @BotFather, получите токен. Узнайте свой числовой Telegram ID. Для каждого пользователя нужен приватный `/start`; ADMIN_ID должен написать боту, иначе Telegram не доставит уведомления.
3. Подключитесь к роутеру по SSH и установите зависимости:

```sh
opkg update
opkg install python3 ca-bundle
/opt/bin/python3 -c 'import ssl, urllib.request, http.server; print("Python SSL OK")'
```

Если сборка Entware разделяет стандартную библиотеку по пакетам, установите недостающие модули из своего feed. Не отключайте проверку TLS. Этот проект не требует aiogram/aiohttp/pip.

4. Скопируйте и распакуйте архив в каталог на Entware-накопителе, например `/opt/tmp/keenetic-awg-bot`. Из него:

```sh
sh install.sh
vi /opt/etc/awg-bot.conf
chmod 600 /opt/etc/awg-bot.conf
/opt/bin/python3 /opt/awg-bot/run.py --check
/opt/etc/init.d/S98awgbot start
/opt/etc/init.d/S98awgbot status
```

Конфиг — буквальные `KEY=VALUE`, без кавычек, shell-подстановок и inline-комментариев. Обязательны BOT_TOKEN, ADMIN_ID, AWGM_URL, AWGM_API_KEY. Для AWGM на том же роутере используйте `http://127.0.0.1:2222` с реальным портом. Завершающее `/api` также допустимо. Другие администраторы: `ALLOWED_IDS=123,456`. Сначала проверьте бот без WEBAPP_URL.

Init-скрипт автоматически вызывается Entware при старте. Команды: start, stop, restart, status. Это обычный init.d-сервис без watchdog: после аварийного завершения требуется start. При старте сохраняется одна предыдущая копия служебного лога. В рабочем режиме запросы/токены в лог не записываются.

## HTTPS и Mini App

### Обновление установленного бота

Один раз установите версию с управлением серверами и обновлениями:

```sh
curl -fsSL https://raw.githubusercontent.com/VladimirRabcun/keenetic-awg-bot/main/update.py -o /opt/tmp/awg-bot-update.py && /opt/bin/python3 /opt/tmp/awg-bot-update.py
```

После этого используйте Mini App: **Меню → Настройки → Обновление бота → Проверить обновления → Установить обновление**. Установка доступна только ADMIN_ID. Версия бота независима от версии AWGM, которую показывает шапка.

Обновление использует release.json из этого репозитория: фиксированный commit и SHA-256 каждого файла приложения. Произвольные URL, команды и пути от клиента не принимаются. Все файлы скачиваются и проверяются до остановки сервиса. Отдельный процесс переживает остановку бота, сохраняет резервную копию, проверяет запуск и восстанавливает предыдущие файлы при ошибке. Прогресс доступен в панели после восстановления соединения. Конфиг, токен, API-ключ и правила маршрутизации не заменяются. Нельзя одновременно запустить два обновления из панели.

Для будущего релиза увеличьте awgbot/version.py и опубликуйте release.json со снимком 15 разрешённых файлов; снимок содержит согласованную версию всех Python-модулей и Mini App. Хэши подтверждают целостность относительно манифеста; источник доверия — HTTPS и доступ к этому GitHub-репозиторию.


После обновления закройте Mini App полностью и откройте кнопкой «Панель» снова. Данные и функции по-прежнему предоставляются только через существующий API AWG Manager; работающий туннель не означает успешную проверку связности.

Mini App требует доступный клиенту HTTPS URL с доверенным сертификатом. Backend слушает только `127.0.0.1:8787`. Пример TLS reverse proxy: `entware/nginx.conf.example` — включите его в `http {}` вашего nginx, заменив домен и пути сертификатов. Выпуск и продление сертификата выполняются вашей системой; сертификаты не включены в архив.

Настройте DNS домена и доступ к TLS reverse proxy (порт 443), затем укажите `WEBAPP_URL=https://vpn.example.com/`, перезапустите сервис и снова отправьте `/start`. Открывайте кнопку «Открыть панель». В @BotFather при необходимости задайте этот же URL как Main Mini App / menu button. Корень сайта должен соответствовать корню backend; размещение в подпапке не поддерживается.

Не публикуйте порт AWGM и 8787. На CGNAT нужен существующий HTTPS-туннель или внешний reverse proxy с защищённым доступом к роутеру; проект не настраивает такой сервис автоматически. Reverse proxy должен сохранять Authorization и не записывать его. Для отдельного proxy-хоста меняйте WEBAPP_HOST на приватный адрес только с firewall, разрешающим доступ исключительно от proxy.

## Защита секретов

Конфиг хранится с 600; приложение на Unix откажется читать доступный другим пользователям файл. Установщик сохраняет существующий конфиг. Секреты не передаются frontend и не помещаются в URL Mini App. Backend проверяет HMAC initData, срок (default 3600 секунд), числовой ID и whitelist на каждом запросе. Дубли полей и время из будущего отклоняются. После часа откройте панель заново. Проверьте синхронизацию часов роутера.

Telegram-команды доступны только в личном чате владельца ID; группы запрещены. Ввод пользователя никогда не запускается как shell-команда. API AWGM допускает только фиксированные операции, ID проверяется по актуальному списку. Redirect AWGM запрещён, чтобы не переслать Bearer-ключ на другой адрес. POST-действия не повторяются автоматически после timeout: обновите список, чтобы узнать фактический результат.

При старте polling отбрасывает команды, накопленные во время отключения сервиса, чтобы не выполнить устаревшее управление туннелями. Используйте только один запущенный экземпляр бота с данным токеном; webhook для этого бота должен быть выключен в Telegram Bot API.

Карточки строятся из `/tunnels/list`, а `/tunnels/get` и экспорт конфигов не запрашиваются. Ответы дополнительно очищаются от полей ключей/секретов. Логи и диагностические отчёты могут содержать чувствительные IP/текст, добавленный самим AWGM; они доступны только администраторам, но автоматическая очистка произвольного текста не гарантируется. Не пересылайте их публично.

HTTP к удалённому AWGM по умолчанию запрещён. Используйте HTTPS; `ALLOW_REMOTE_HTTP=true` предусмотрен только для осознанного использования в защищённой сети. Root Entware и резервные копии накопителя могут читать конфиг. При утечке отзовите оба токена. Используйте отдельный API-ключ для бота.

## Проверка и ограничения

```sh
cd /opt/tmp/keenetic-awg-bot
/opt/bin/python3 -m unittest discover -s tests -v
```

Тесты проверяют подпись/срок/whitelist, отсутствие секретов в карточках, методы и URL AWGM на локальном mock HTTP-сервере и доступ к Mini App. `--check` читает /health и /tunnels/list с вашим реальным ключом. Интеграция с физическим Keenetic и реальным Telegram требует ваших настроек и не была выполнена при сборке.

Если AWGM отвечает 401 — проверьте ключ; 404/405 — версию и `docs/API.md`; connectivity может длиться до 65 секунд. Диагностика запускается фоново: после запуска отдельно открывайте статус и отчёт, пока сбор не завершён. Неподдерживаемый endpoint показывает ошибку, подмена результата фиктивными данными отсутствует.

## Обновление и удаление

Остановите сервис, сделайте приватную резервную копию `/opt/awg-bot`, замените `awgbot/` и `run.py` новой версией, обновите init-скрипт, затем выполните `--check` и start. Конфиг и STATE_DIR сохраняйте. Для удаления остановите сервис и удалите именно `/opt/awg-bot`, `/opt/etc/init.d/S98awgbot`, `/opt/etc/awg-bot.conf`, `/opt/var/lib/awg-bot` и записи reverse proxy. Отзовите ключ AWGM и токен бота, если больше не используете их.

## Структура

`config.py` — конфиг, `access.py` — initData, `awgm.py` — REST-клиент, `panel.py` — общий диспетчер, `bot.py` — Telegram polling/меню, `monitor.py` — уведомления, `webapp.py` — ограниченный HTTP backend, `static/` — Mini App. Polling, мониторинг и web-сервер работают в отдельных потоках; управление туннелями сериализовано. До 8 одновременных web-запросов, тело до 8 KiB, ответ AWGM до 2 MiB.

Документированные контракты и источники: [docs/API.md](docs/API.md). Лицензия собственного кода: MIT.


### Серверы и версия AWGM

Серверы AWGM: создание, изменение имени/адреса/маски/UDP-порта/endpoint/DNS/MTU, start/stop/restart и удаление с клиентами. Настройки доступа: NAT, политика роутера, LAN-сегменты. ASC редактируется как JSON с текущими полями API; создание может автоматически сгенерировать ASC.

Серверы Keenetic: start/stop/restart, endpoint, NAT, политика доступа и клиенты. API AWGM не предоставляет создание, удаление или изменение базовых параметров системного интерфейса: это делается в Keenetic. Панель не имитирует отсутствующие операции.

Клиенты обоих типов: добавление, изменение имени/адреса/DNS/AllowedIPs/сетей за клиентом, отключение/включение, удаление, сигнатура и выгрузка .conf. Приватные ключи скрываются в списках и ответах обычных операций. Конфиг с ключами возвращается только отдельным авторизованным запросом после явного подтверждения экспорта; он не сохраняется в localStorage и удаляется из интерфейса при закрытии окна. Для клиентов без сохранённого секрета кнопка экспорта скрывается, когда API явно сообщает confAvailable=false.

Пустой выбор LAN-сегментов закрывает доступ в LAN. Посторонние ACL на сервере могут разрешать больше — форма показывает их, если API их возвращает. Изменение DNS, сетей или сигнатуры требует заново выгрузить конфиг на клиент. Удаление сервера/клиента подтверждается в интерфейсе; обычный restart может прервать соединение клиентов. Перезапуск асинхронный: accepted означает принятие команды, состояние обновляется опросом.

Mini App показывает версию AWGM из GET /api/health. Форматы сверены с исходниками тега v2.19.12: https://github.com/hoaxisr/awg-manager/tree/v2.19.12/internal/api . Полный список маршрутов находится в docs/API.md.

### 0.5.0: страница серверов

Выбор сервера, тумблер запуска, действия и сводка 2×2, раскрываемые NAT/LAN/sing-box/политика доступа. Карточки клиентов поддерживают поиск и сортировку по handshake, имени, трафику и IP. Экспорт/импорт управляемых серверов доступны только ADMIN_ID: JSON содержит приватные ключи. Импорт до 900 КБ, опциональное переназначение интерфейсов, отчёт о частичных конфликтах. Настройки → Обновление бота устанавливает новую версию с проверкой файлов и откатом при ошибке.
